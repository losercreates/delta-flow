# Phase 1: Data Model & State Transitions: Real-Time Streaming & Chaos Control

## 1. Domain Entities & DTO Structures

### 1.1 Chaos Experiment DTOs

#### `ChaosStatusDto`
Represents the current health and active chaos conditions across system proxies and resilience circuits.
```typescript
interface ChaosStatusDto {
  toxiproxyEnabled: boolean;
  activeToxicsCount: number;
  proxies: ProxyStatusDto[];
  circuitBreakers: CircuitBreakerStatusDto[];
}

interface ProxyStatusDto {
  name: string;
  listenAddress: string;
  upstreamAddress: string;
  enabled: boolean;
  activeToxics: ToxicDetailDto[];
}

interface ToxicDetailDto {
  name: string;
  type: 'latency' | 'packet_loss' | 'slicer' | 'bandwidth' | 'timeout';
  stream: 'DOWNSTREAM' | 'UPSTREAM';
  toxicity: number; // 0.0 to 1.0
  attributes: Record<string, unknown>;
}
```

#### `ChaosInjectionRequest`
Payload submitted by operators to inject faults into a proxy.
```typescript
interface ChaosInjectionRequest {
  proxyName: string;
  toxicType: 'LATENCY' | 'PACKET_LOSS' | 'PARTITION';
  latencyMs?: number;
  jitterMs?: number;
  dropRate?: number; // e.g. 0.30 for 30%
  operatorId: string;
  justification: string;
}
```

#### `CircuitBreakerTransitionRequest`
Payload submitted by operators to manually force a circuit breaker transition.
```typescript
interface CircuitBreakerTransitionRequest {
  targetState: 'OPEN' | 'CLOSED' | 'HALF_OPEN';
  operatorId: string;
  justification: string;
}
```

```typescript
interface InvariantVerificationReport {
```

### 1.3 Dead-Letter Queue (DLQ) Structures

#### `DeadLetterOutboxEventDto`
Represents an outbox record routed to the DLQ after exceeding maximum publication retries.
```typescript
interface DeadLetterOutboxEventDto {
  eventId: string;
  sagaId: string;
  tenantId: string;
  eventType: string;
  topic: string;
  partitionKey: string;
  payload: string;
  retryCount: number;
  errorDetails: string | null;
  createdAt: string;
  updatedAt: string;
}
```

#### `DlqReplayRequest`
Payload to replay a dead-lettered event.
```typescript
interface DlqReplayRequest {
  operatorId: string;
  justification: string;
}
```

### 1.4 Dashboard Live Event Envelope

#### `DashboardLiveEvent`
Unified SSE message structure broadcast to all connected operators.
```typescript
interface DashboardLiveEvent {
  eventId: string;
  eventType: LiveEventType;
  sagaId: string | null;
  tenantId: string | null;
  timestamp: string;
  payload: Record<string, unknown>;

type LiveEventType =
  | 'SAGA_STARTED'
  | 'SAGA_STATE_CHANGED'
  | 'STEP_STATE_CHANGED'
  | 'SAGA_SUSPENDED'
  | 'SAGA_RESUMED'
  | 'SAGA_TIMED_OUT'
  | 'SAGA_COMPENSATED'
  | 'SAGA_COMPLETED'
```

## 2. State Transition Diagrams

### 2.1 Chaos Experiment Lifecycle
```
[HEALTHY / BASELINE]
       │
       ▼ (Operator POST /api/v1/chaos/inject)
[CHAOS ACTIVE (Latency / Packet Loss / Partition)]
       │
       ├──► (Automatic or Manual Circuit Breaker Trip: CLOSED -> OPEN)
       │
       ▼ (Operator POST /api/v1/chaos/heal)
[HEALTHY / BASELINE] (All toxics cleared, audit event emitted)
```

### 2.2 DLQ Poison Event Lifecycle
```
[OUTBOX: PENDING]
       │
       ▼ (Repeated broker dispatch failure >= max_retries)
[OUTBOX: DEAD_LETTER]
       │
       ▼ (Operator POST /api/v1/dashboard/dlq/{id}/replay)
[OUTBOX: PENDING] (retry_count reset to 0, immediate sweep dispatched)
       │
       ▼ (Broker receives event)
[OUTBOX: PUBLISHED]
```
